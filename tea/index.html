TEA: Structurally Representing Arbitrary LLM Agents Collaboration

A flexible structural representation that makes evolving collaboration explicit - coupling an Agent Interaction Graph to a Task Activity Graph and the shared environment - without prescribing agent reasoning, behavior, or communication order. Infuse builds on TEA to recover, assess, and improve collaboration policies.

Collaboration Structure Emerges During Execution

Giving multiple agents a joint task in a shared environment does not automatically make them collaborate. Collaboration emerges when agents coordinate their contributions: LLM agents create tasks, communicate progress, and divide and carry out work. Understanding and improving such collaboration requires tracking the relationships between agents' interactions, task changes, and effects on the environment - without constraining execution.

In practice, a collaboration policy guides these interactions, as an executable graph or as code and instructions. It may be fully specified, partially specified (an orchestrator decomposes and assigns work on the fly), or open-ended (agents organize collaboration by themselves). Flexible policies exploit agents' ability to adapt, but they make collaboration hard to track - and agents may deviate even from a predefined workflow.

TEA (Task-Environment-Agents) connects an event-based model of asynchronous agent interactions to a task graph that agents create and modify, grounding both in the shared environment. It preserves task identities and versions, attributes task changes to agent activations, and lets agents attach evidence to task versions as signals of progress.

1

An Agent Interaction Graph coupled to a Task Activity Graph and the environment, forming a collaboration state that supports analysis and optimization.

2

A formal definition of collaboration policies; TEA represents a large class of agent interactions and supports policy recovery and discovery through topology reconstruction, inferred execution rules, and cross-layer queries.

3

TEA records diverse interaction and task structures and correctly recovers their topology and policy properties.

TEA doubles as an interface for agent collaboration. Infuse recovers a policy from TEA traces, assesses it against task progress and environmental outcomes, and updates it.

Task-Environment-Agents

A TEA record of a collaboration process ties together three layers, an evidence relation, and the tools that connect them. Agents are the common actors across all three layers.

DT = (D, T, Z, Φ, U)    interaction graph · task graph · environment · evidence attachments · tool space
T

Task Activity Graph TAG

A directed bipartite graph of task versions and task actions. A version q = (k, δ, σ) carries a persistent task identity, a specification of goal and evaluation rule, and a state. Versions are immutable: every revision appends a new version linked to its inputs, so branching and merging work keeps its history.

D

Agent Interaction Graph AIG

A directed bipartite graph of events and activations. An activation is one reasoning cycle of an agent: it records the reasoning interval, received events, and ordered tool calls with their results. Events carry any payload, including tool results and messages, and can wake other agents into new activations.

Z

Shared Environment Env

The world agents observe and change through environment tools. Environment calls return fresh events into the AIG, so task declarations and evidence stay connected to externally verifiable effects.

Tools couple the layers

Besides task tools and environment tools, TEA provides communication and evidence tools. sendh(e, J) delivers an event to agents J - a new message or a forwarded event. attachh(φ) attaches evidence φ = (h, x, q), an arbitrary payload x from activation h, to an exact task version q. Evidence stays attached to that version and does not carry over to later revisions.

Every tool call is recorded in its issuing activation together with the events it returns, so the AIG is updated by every call; task and environment calls additionally update the TAG and the environment.

A small vocabulary for evolving work

Six task tools capture how agents act on tasks. Applications supply the meaning of goals, states, and evaluation rules; the tools capture how work changes without fixing what the work must be.

OPEN(δ, σ)∅ → q

Create a fresh task identity with an initial version.

EDITδ(q, δ′)q → q′

Revise the goal or evaluation rule while preserving the reported state.

UPDATEσ(q, σ′)q → q′

Change the reported state while preserving the task specification.

SPLIT(q, {(kj, δj, σj)})q → {q1, …, qm}

Decompose one version into versions with distinct task identities.

JOIN({qj}, k′, δ′, σ′){q1, …, qm} → q′

Integrate versions from distinct identities into a single successor version.

CLOSE(k)propagate closure

Closure propagates backward through recorded ancestry; a split's parent closes only when all of its children are closed.

Two representation properties. The AIG forms a temporal DAG over activations and events that can represent any finite DAG of activation dependencies, with each output event having exactly one parent activation. The six task tools can represent any finite DAG of task versions, keeping the original dependencies unchanged and adding at most one auxiliary leaf per version with a single predecessor. In both, timestamps consistent with the dependencies are recorded as annotations.
Evidence and task progress. For a task version q, the attached evidence Φq, its providers, and its content together provide signals of task progress. Interpretations from different agents may agree, partially agree, or disagree, and different interpreters at different times may weight evidence from distinct sources differently.

Recovering and Discovering Collaboration Policies

Each agent follows its own policy, deciding from its available information and private state. For a given team, task, and setup, the resulting collective behavior follows a joint distribution over when agents activate, what they receive, which tools they call, and what they send to whom and when.

Collaboration policy for LLM agents. For a fixed agent team, task, and execution setup, a collaboration policy Γ is an interaction topology along with a set of coordination rules that together guide or constrain task execution, shaping the joint distribution of agent activations, tool calls, and event exchanges over time.

Topology recovery through aggregation

Take the activations that start and finish within a window [t, t′] and merge them by agent. The result is a weighted graph G[t,t′] = (V, E, w) whose edges connect agents that exchanged messages, weighted by message counts. The full agent topology is recovered once the selected records cover every edge that the policy Γ can create.

Inferring execution rules

Starting from the recovered topology, TEA examines activation times, send and receipt records, and recorded decisions in the trace. Consecutive activations whose starts fall within τ of each other and whose intervals share a common overlap are grouped. For completed activations on a common clock, with start sh and finish fh:

h ≺ h′  iff  fh ≤ sh′ (execution order) h ∥τ h′  iff  |sh − sh′| ≤ τ (overlap)

Sequential

Apply ≺ along activation paths. Both ha,1 ≺ hc,1 ≺ ha,3 and ha,3 ≺ hc,2 ≺ ha,4 support the local order a → c → a.

Parallel

Apply ∥τ: hc,1 overlaps hb,1, ha,2, and hb,2. Agent a can receive b's result and send more work to b while c remains active.

Repetition

Follow message paths that return to later activations of the same agent. The path ha,1 → hb,1 → ha,2 → hb,2 → ha,3 contains a → b → a twice.

Conditional

The graph shows whom an agent sends to; the conditions behind each message are inferred from its input messages and subsequent sending behavior.

Joins

Observe which senders provide inputs to an agent's activations and how consistently those sets recur. ha,3 receives from both b and c: recurring both-inputs support an all-input rule, either alone an any-input rule.

Analyzing relationships in TEA

Agents' activities induce directed graph edges (→) and implicit links (↦) across TEA; a task tool call, for example, is recorded in the AIG and creates a corresponding action node in the TAG.

Paths and queries. Queries traverse these edges and links in either direction, within or across layers. Each path between two entities gives an interpretation of their relationship based on its link types and traversal directions. Tracing task versions reveals who worked on a task, what they changed and in what order, and the linked evidence and environmental feedback. Tracing further back to agent activations shows whom they interacted with and what information they received, helping explain their actions.

Infuse: Learning Collaboration Policies from TEA Records

TEA is not only a record. Instantiated as a collaboration framework, it is the interface through which agents communicate, transform tasks, and act in the environment - and Infuse uses the resulting trace to propose a better collaboration policy.

TEA as a collaboration framework

A team of agents collaborates asynchronously through TEA. During an activation, an agent acts on its environment view, its TAG view, received messages, and private memory. Its tool calls support communication, task transformations, evidence attachment, and environmental actions - all recorded through TEA. Three mechanisms control when agents activate:

  1. After each round of reasoning and tool use, the agent decides whether to continue its current activation or deactivate.
  2. The sleep operation ends the current activation and schedules reactivation after a specified delay.
  3. When sending a message, the agent specifies whether it should interrupt the recipient. Delivery activates an inactive recipient; if the recipient is active and interruption is requested, its current activation ends and a new one begins with the incoming message.

Infuse

Infuse improves the task performance of an LLM agent team in an open-ended setting, starting from an empty collaboration policy. It refines how the agents collaborate by analyzing the resulting execution records and proposing an updated policy. Because TEA grounds the AIG and TAG in environmental outcomes, Infuse can check the recovered policy against the trace and assess its components, guiding what to keep, add, revise, or leave open.

In the paper's implementation, a separate gpt-6-sol agent consolidates this guidance into global lessons for the team and private lessons for individual agents, forming the proposed policy Γ′. Infuse itself is agnostic to the algorithm that produces Γ′.
1

Execute and record

DT ← fexecute(V, Γ)

The agent team V attempts the task under policy Γ - possibly empty - and TEA records the collaboration as it unfolds.

2

Recover / discover

Γ̂ ← frecover(DT)

Aggregate activations by agent to recover the observed interaction topology and infer candidate execution rules from the trace.

3

Analyze and propose

Γ′ ← fanalyze(Γ, Γ̂, DT)

Query the record to compare the recovered policy with the trace, assess coordination against task progress and environmental outcomes, and propose the next policy.

Experiments

Representation experiments test whether TEA preserves agent interactions and task histories and supports coordination recovery. Empirical experiments test whether TAG improves open-ended collaboration and whether Infuse can discover and improve a collaboration policy.

Representation experiments

Different collaboration policies are implemented as LangGraph workflows that specify interaction graphs, coordination rules, and how agents process tasks. The workflows are executed and the resulting TEA traces are visualized.

Queries

In the recovered record, the inferred rules show repetition and execution order, and checking TAG states helps explain conditional routing. Asking "Who worked on task k2, and why?", the record shows that the planner creates k2 by splitting k1 and sends messages to both workers. In the first round, worker1 is the only worker that acts in the environment; it updates k2 and then sends a message to the verifier.

Policies that change mid-task

A task may have several milestones that benefit from different collaboration policies. Aggregating interactions over reasonable chunks recovers the policy in each phase, while chunks that cross phases can greatly affect the recovered topology. This opens up opportunities in detecting policy changes and selecting aggregation windows.

Empirical experiments

Task performance is evaluated in two domains, using TEA as an open-ended collaboration framework and Infuse to improve the collaboration policy. Both domains use five gpt-5.6-terra agents without predefined roles. A separate gpt-6-sol agent derives Infuse guidance from execution records and outcomes.

Domain 1

Code refactoring

Agents modularize a correct but redundant codebase; performance is LoC reduction while passing fixed tests. Six repositories span three difficulty levels by repository size. Agents share all files but may modify only source code, using list_files, read_file, edit_file, measure, and run_tests, with a budget of 100 total agent steps.

Domain 2

Silo-Bench

30 distributed reasoning tasks across three difficulty levels. Each agent accesses local information through read_data and uses submit to answer a query that requires information from across the team. Reported: task success rate (all agents correct), S (fraction of exactly correct answers), and P (mean score with partial credit).
